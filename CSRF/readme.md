# Cross-Site Request Forgery (CSRF)

## Objective

To demonstrate a CSRF attack against the password-change
functionality of DVWA in a controlled laboratory environment.

## Attack Scenario

CSRF occurs when an application accepts a state-changing request
without sufficiently verifying that the request was intentionally
made by the authenticated user.

## Demonstration

The DVWA CSRF functionality was tested using a temporary lab
password.

Burp Suite was used to intercept and inspect the HTTP request
generated by the password-change operation.

The request contained parameters associated with changing the
password.

## Observation

The HTTP request could be captured and inspected using Burp Suite.
This demonstrated how a state-changing request is transmitted by
the application.

## Mitigation

### CSRF Token

The application should generate a unique and unpredictable CSRF
token for state-changing requests.

The server should verify the submitted token before processing the
request.

Additional protections include:

- SameSite cookies
- Origin/Referer validation
- Re-authentication for sensitive actions

## Testing Environment

- Kali Linux
- DVWA
- Docker
- Burp Suite
- Local controlled laboratory
